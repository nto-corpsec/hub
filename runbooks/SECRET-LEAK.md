# Runbook: утечка секрета

> Удаление файла коммитом **не** отменяет компрометацию. Сначала ротация.

## 1. Ротация (немедленно)

| Что утекло | Действие |
|---|---|
| GitHub PAT / OAuth | Revoke в Settings → Developer settings, выпустить новый |
| SSH-ключ | Удалить из GitHub, сгенерировать новую пару |
| Токен стороннего сервиса | Revoke в панели сервиса, перевыпуск |
| Пароль | Сменить, включить 2FA, проверить сессии |
| Приватный ключ TLS | Перевыпустить сертификат |

Проверить журналы использования: не было ли действий с токеном после утечки.

## 2. Локализация

```bash
git log --all --oneline -S 'ИСКОМЫЙ_ФРАГМЕНТ'
git log -p --all -S 'ИСКОМЫЙ_ФРАГМЕНТ' -- .
```

Определить: коммит, ветки, теги, форки, релизы, артефакты CI.

## 3. Очистка истории

```bash
# в отдельной копии, не в рабочем дереве
git clone --mirror git@github.com:ORG/REPO.git repo.git
cd repo.git
git filter-repo --invert-paths --path path/to/leaked.file
# либо по содержимому:
# git filter-repo --replace-text <(echo 'СЕКРЕТ==>REDACTED')
git push --force --all
git push --force --tags
```

После force-push: попросить всех переклонировать, старые объекты удалить через
GitHub Support (если репозиторий публичный — считать секрет скомпрометированным навсегда).

## 4. Проверка

- [ ] Секрет отозван и недействителен
- [ ] В истории `main` и всех веток фрагмента нет: `git log --all -S`
- [ ] Форки проверены и удалены/очищены
- [ ] Артефакты CI с секретом удалены
- [ ] GitHub Secret Scanning alert закрыт (если был)
- [ ] Запись в `ops/notes/incidents.md`

## 5. Профилактика

- gitleaks в каждом PR (уже в CI).
- Никогда не коммитить `.env`; в репозитории только `.env.example`.
- Секреты — только в GitHub Secrets окружений, с ограничением по ветке.
