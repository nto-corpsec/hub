# Runbook: поток флага/ответа

Цель — не потерять ответ, не засветить его и не отправить дважды.

## Схема

```
solve → verify (второй человек) → record (ops) → submit (платформа) → log
```

## 1. Solve

Работаешь в `ops` (приватно) или локально. В публичные репозитории не попадает ничего,
что содержит ответ, флаг, номер задания или уникальную строку из условия.

## 2. Verify

Второй участник воспроизводит с нуля по твоей инструкции. Если не воспроизвёл —
ответ не отправляем.

## 3. Record

В `ops/answers/<task-id>.md`:

```yaml
task: 12
role: websec
answer: <значение>
confidence: high
verified_by: dfir
time_spent: 35m
evidence: ops/evidence/12/screenshot.png
```

## 4. Submit

Сдаёт лид или назначенный на задачу. Один человек — один канал, чтобы не дублировать.
После отправки — скриншот подтверждения в `ops/evidence/<task-id>/`.

## 5. Log

Строка в `ops/notes/timeline.md`: время, задача, результат, кто сдал.
Это же попадает в итоговую сводку и ретро.
