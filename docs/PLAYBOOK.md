# Playbook

## Рабочий день

| Время (NSK) | Что |
|---|---|
| 09:00 | Синк 15 минут: вчера, сегодня, блокеры. Итог — комментарии в issues |
| 09:15–11:00 | Блок 1: самая тяжёлая задача дня (deep work, без чатов) |
| 11:00–11:15 | Разбор `priority/p0`, передача контекста |
| 11:15–14:00 | Блок 2: параллельная работа ролей |
| 14:00–15:00 | Обед, асинхронные ответы |
| 15:00–17:30 | Блок 3: интеграция, ревью, исправления |
| 17:30–18:00 | Окно мержа: PR в `main`, проверка CI, обновление доски |
| 21:00 | EOD-заметка: что сделано, что осталось, где артефакты |

## Правила игры

- **Таймбокс 25/5.** Не решил за 25 минут — пиши в issue, зови вторую голову.
- **Правило двух.** Любой ответ проверяет второй человек до отправки.
- **Стоп-кран.** Если задача не двигается 40 минут — статус `status/blocked` и тег лида.
- **Одна задача в работе.** WIP-лимит на человека — 1, у лида — 2.
- **Никакой самодеятельности в инфраструктуре.** Изменение CI/rulesets — через PR в `hub`/`.github`.

## Коммуникации

| Канал | Для чего | SLA |
|---|---|---|
| GitHub issue | Вся работа, решения, артефакты | 2 часа |
| Голосовой созвон | Блокер, разбор в реальном времени | сразу |
| `#incident` | Только инциденты с секретами/доступами | 15 минут |
| Личные сообщения | Не для работы: решения теряются | — |

Всё, что решили голосом, в течение 10 минут попадает в issue.

## Передача смены (handoff)

Комментарий в issue по шаблону:

```
HANDOFF
Состояние: <что готово>
Артефакты: <пути/ссылки>
Следующий шаг: <конкретное действие>
Риски: <что может сломаться>
Кому: @role
```

## День этапа

1. 08:45 — стенд поднят, логи пишутся, место на диске проверено.
2. 09:00 — распределение задач, фиксация в issues.
3. Каждые 2 часа — короткий статус в issue, а не в чат.
4. За 30 минут до дедлайна — стоп новым задачам, только сдача и проверка.
5. После — ретро по шаблону, не позже следующего утра.
