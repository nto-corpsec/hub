# ADR-0002: гибридная топология репозиториев

- **Статус:** принято
- **Дата:** 2026-10-26
- **Контекст:** 5 ролей, 4 недели, разные наборы инструментов и разный темп изменений

## Проблема

Монорепо упрощает координацию, но смешивает историю и заставляет гонять все проверки на
каждое изменение. Репозиторий на роль даёт изоляцию, но плодит дублирование конфигов.

## Решение

Гибрид из четырёх слоёв:

| Слой | Репозиторий | Почему отдельно |
|---|---|---|
| Процесс и знания | `hub` | Меняется ежедневно, ревьюится лидом, не должен блокироваться кодом |
| Инструменты | `arsenal` | Общий Python-пакет и CI; CODEOWNERS по папкам ролей |
| Стенды | `lab` | Тяжёлые зависимости и docker-compose, отдельный цикл жизни |
| Шаблоны | `tpl-*` | Версионируются независимо, используются через «Use this template» |

Плюс приватный `ops` для ответов и доказательств.

## Последствия

- Четыре независимых пайплайна вместо одного — меньше взаимных блокировок.
- Общие проверки вынесены в reusable workflows репозитория `.github`.
- Нужен один «владелец инфраструктуры» — лид; изменения CI только через PR.
- При росте команды можно добавить `role-*` репозитории без перестройки.
